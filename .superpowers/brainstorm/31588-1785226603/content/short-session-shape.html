酒馆短牌：状态数据分层

这一节只定结构边界。目标是把“酒馆里的持续筹码局”与“单手牌规则引擎”拆开，避免 short/long 共用一堆互相污染的字段。

三层状态边界
House Session
TavernSessionState
负责酒馆 UI、入口 overlay、选中的玩法、玩家这次准备兑换多少文钱、是否显示“继续下一局 / 再兑换 / 退出结算”。

这里不直接处理发牌、抢牌、边池。
短牌桌 Session
ShortTableSession
负责持续筹码：当前剩余筹码、累计兑换金钱、手数、庄位轮转、是否还能再开一手、退出时能换回多少文钱。

它持有当前这手的 currentHand。
单手牌 State
ShortHandState
只负责一手牌：52 张牌堆、4 家手牌、2 张公牌、下注轮次、摸打轮次、抢牌链、边池、摊牌结果。

一手结束即可丢弃，不承担跨手结转逻辑。
单手牌内部核心对象
PlayerState
seat / name / privateHand(恒 5 张) / stack / committedThisRound / committedThisHand / folded / allIn / discardHistory / lastAction
ClaimChain
lastDiscard / claimCandidates / claimPriority / originNextSeat / chainDepth。用于连锁吃碰杠，直到无人响应再回主轮转。
PotState
mainPot + sidePots[]。每个 pot 记录金额和可争夺玩家集合，便于 all-in 与杠惩罚一起结算。
ShowdownState
7 选 5 最佳牌型、比较键、每个 pot 的赢家、分池明细、最终筹码变化。
与现有 tavern house 的连接方式
`tavern-house-module` 继续负责把领域状态映射成 `gamble-table` overlay；但 `gamble-table` 内部改成 variant-specific payload：

short 显示：筹码、当前 pot/side pot、2 张公牌、5 张手牌、可抢牌动作、牌型结果。
long 继续显示原来的麻将字段，不和 short 共用“番型/出组/公共牌窗”语义。
