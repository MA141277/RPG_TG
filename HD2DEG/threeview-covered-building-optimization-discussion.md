# 带盖建筑内部细节重建问题优化讨论

## 背景

当前流程可以概括为：

1. 先用生图模型生成目标建筑的三视图 `front / side / top`
2. 再基于三视图做体素正交求交或近似视觉壳体重建
3. 最后做外壳提取、着色和渲染

这个流程在做低精度、外轮廓明确、偏实心的体块建筑时很高效，但一旦目标是**带盖建筑**，尤其是存在下列情况时，就会明显失效：

- 屋顶遮挡了中庭、天井、回廊、内院等内部结构
- 建筑存在挑檐、骑楼、雨棚、塔楼镂空、屋顶下二层退台
- 外部三视图能看到的只是外壳，内部细节没有直接可见证据
- 生图模型生成的三视图并不严格几何一致，细节在三个视图中的表达存在冲突

本质上，这不是单一算法实现问题，而是**输入信息不充分 + 当前重建表达过于刚性**共同导致的问题。

---

## 一、为什么当前体素正交算法不擅长还原带盖建筑内部细节

### 1. 三视图求交天然偏向“外轮廓一致的实心体”

经典规则通常类似：

\[
occupied(x,y,z)=front(x,y)\land side(z,y)\land top(x,z)
\]

这类规则适合重建“所有方向都能观察到的共有体积”，但对于被屋顶遮挡的内部空间，`top` 视图通常只会告诉算法“这里有屋顶覆盖”，而不会告诉算法“屋顶下面其实是空的”。

因此算法会更倾向于把这块区域填成：

- 实心
- 厚壳
- 单层封闭体

而不是：

- 中空屋盖
- 带内院的围合结构
- 屋顶下有柱廊或挑空空间

### 2. 当前输入只描述“可见表面”，没有表达“隐含结构”

生图模型生成的三视图本质上更像是：

- 外观草图
- 贴图参考
- 可见面投影

而不是严格意义上的工程三视图。对于“屋顶下方是否中空”“里面是否有天井”“檐下是否有柱列”这类信息，图像通常没有显式编码。

也就是说，当前管线把**图像可见性问题**直接当成了**几何占据问题**，中间少了一层“结构推理”。

### 3. 屋顶类元素在 `top` 视图中具有压倒性覆盖效应

对建筑来说，`top` 视图常常最强势，因为：

- 屋面连续且面积大
- 屋檐会扩张投影范围
- 生图模型喜欢把顶视画成完整盖板

于是 `top` 对占据判断的影响会非常大，导致：

- 中庭被盖死
- 檐下走廊被填实
- 回字形建筑被误判成实心块

### 4. 单层体素表达分辨率不够，容易吞掉内部小结构

即使从轮廓上推断到“这里可能不是完全实心”，单一分辨率体素也容易出现：

- 细柱无法表达
- 走廊宽度低于 1 到 2 个体素时直接消失
- 屋檐厚度、窗洞、内凹空间被离散化抹平

所以问题不只是“推不出来”，还有“表达不出来”。

### 5. 生图三视图之间通常不严格一致

现实里三张图常见问题包括：

- `front` 有窗廊，`side` 没体现
- `top` 画了完整屋盖，但立面暗示内部中空
- 比例不一致，屋檐出挑在不同视角宽度不同

当前硬求交方法对这种不一致非常脆弱，会把冲突直接变成：

- 误删结构
- 误补实体
- 细节断裂

## 二、在当前方案基础上的优化方向

这一部分重点是不推翻现有“三视图 -> 体素”的主流程，而是在其上增加更适合建筑结构的约束和推理层。

## 2.1 把“硬求交”改成“软融合”

不要把三个视图都当成 0/1 的绝对裁决，而是改成**概率占据**：

\[
P(occ)=w_f\cdot score_f + w_s\cdot score_s + w_t\cdot score_t + w_p\cdot prior
\]

其中：

- `score_f / score_s / score_t` 来自三视图对该体素的支持度
- `prior` 来自建筑先验
- `w_t` 在带盖建筑里不应永远最大

这样可以解决两个核心问题：

- 三视图不一致时不至于一票否决
- 可以显式引入“屋顶下可能中空”的先验

可落地改法：

- 用 alpha、边缘、语义色块替代纯二值 mask
- 对屋面区域降低“必然实心”的权重
- 对立面连续开窗、拱廊、门洞区域增加“内部可通”的概率

## 2.2 从“占据重建”改成“壳体 + 空腔推断”

建筑不是雕塑，很多时候更适合表达为：

- 外墙壳
- 屋盖壳
- 内部空腔
- 局部支撑构件

因此可把当前算法拆成两阶段：

1. 先重建稳定外壳
2. 再做内部空腔和屋盖下空间推断

比起直接在体素层面判断“这里是不是实心”，更实用的做法是：

- 先求视觉一致的外边界
- 再判断哪些体积应该被挖空

尤其适用于：

- 回字形院落
- 带天井的屋顶
- 底层骑楼、上层封闭
- 中殿挑空、两侧有厢房

## 2.3 增加“沿视线的多层占据”而不是单层投影

当前三视图约束默认每条投影线只表达“有或无”，但建筑里更合理的是：

- 外表面一层
- 内部空一段
- 另一侧墙体再一层

也就是一条射线上可能存在**多层结构**。

优化方式：

- 对每个 `front(x,y)` 或 `side(z,y)` 不只记录是否有体素
- 改为记录若干层深度候选，类似 `surface intervals`
- `top` 视图只约束“盖住了哪里”，而不强制其下方全部填满

这会比纯体素 AND 更接近“建筑壳体”而不是“实体块”。

## 2.4 给屋顶单独建模，不要让屋顶直接主导整体占据

带盖建筑中，屋顶既是关键特征，也是主要干扰项。建议把屋顶从主体体块中拆出来：

1. 先从三视图中分离屋顶区域
2. 单独重建屋顶高度、坡向、挑檐轮廓
3. 主体墙体按立面与平面关系重建
4. 最后把屋顶作为上层覆盖件装配回去

这样能明显缓解：

- 屋面覆盖导致中庭被填实
- 檐口投影扩大导致平面误判
- 屋顶纹理被错误解释成实体厚度

如果只做当前体系内的小改动，这一条通常是**收益最高**的。

## 2.5 做建筑语义分层

把输入图像先分成几类再参与重建：

- 屋顶
- 外墙
- 开口
- 柱廊/檐下阴影
- 地基/台座
- 装饰构件

然后使用不同规则：

- 屋顶：优先生成覆盖壳，不直接填实体
- 外墙：更适合生成厚度受限的壳体
- 开口：参与 carving，优先挖空
- 柱廊：允许下方通透

如果没有现成语义分割模型，也可以先用更轻量的方法：

- 固定色板约束生图输出
- 让三视图按类别出图
- 通过 prompt 或后处理让“屋顶 / 墙 / 窗 / 阴影”颜色编码稳定

这属于对现有流程改动不大，但非常有效的工程优化。

## 2.6 引入建筑拓扑先验

很多建筑虽然细节不同，但拓扑模式有限，比如：

- 实心塔楼
- 回字院
- 中殿 + 两翼
- 沿街骑楼
- 底层开敞、上层封闭

因此可以准备一个**建筑拓扑模板库**，让三视图不是直接生成最终体素，而是先匹配到一种结构原型，再做参数化变形。

例如先判断它更像：

- `solid_block`
- `courtyard`
- `arcade`
- `tower_with_roof`
- `hall_with_side_wings`

再在该原型上调：

- 开间数
- 柱距
- 屋顶覆盖范围
- 内院大小
- 楼层退台

这会显著降低“从不充分图像直接猜完整内部结构”的难度。

## 2.7 使用分层分辨率或八叉树，不要全局同精度

在建筑重建里，不同区域需要的分辨率不同：

- 大墙面、屋面可以低分辨率
- 柱廊、窗洞、屋檐转折需要高分辨率

所以可以改成：

- 全局低分辨率体块定位大结构
- 局部高分辨率 refinement 修正檐下、洞口、回廊
- 最终再做统一 mesh 或表面提取

这比一开始全局高精度体素更省，也更适合“中间细节只在局部重要”的问题。

## 2.8 从“体素实体”切换到“体素壳 + 程序化补全”

对建筑来说，很多内部细节并不需要完全由图像恢复，而可以程序化生成：

- 檐下柱列按间距重复
- 回廊按平面环绕生成
- 窗洞按立面节奏复制
- 屋顶坡面由主脊、檐口推导

推荐的混合流程是：

1. 三视图只负责确定主轮廓、风格、构图
2. 体素壳体负责确定大致体积
3. 程序化规则负责补足柱廊、洞口、内院等规律性结构

如果项目目标是可控的游戏资产，而不是学术级纯重建，这往往比“纯图像反演所有细节”更靠谱。

## 三、优先推荐的“现有方案增强版”

如果希望尽量复用现有代码和思路，建议按以下优先级推进。

### 方案 A：屋顶分离 + 壳体重建 + 空腔 carving

这是最建议优先做的版本。

流程：

1. 三视图预处理，分离屋顶和主体
2. 主体按立面和顶视重建外墙壳
3. 根据开口、廊柱、院落迹象做内部挖空
4. 屋顶单独作为覆盖层装回

优点：

- 对当前流程改动相对可控
- 能直接缓解“带盖建筑中心被填死”
- 对中庭、骑楼、檐下空间帮助最大

缺点：

- 需要一定的语义分层能力
- carving 规则需要反复调参

### 方案 B：概率体素 + 建筑先验打分

流程：

1. 三视图不再输出硬二值占据，而是输出 soft score
2. 对候选体素引入建筑先验分数
3. 通过能量最小化或迭代搜索得到最终占据

优点：

- 更稳健，能处理视图冲突
- 更容易引入“屋顶下可能是空的”这种知识

缺点：

- 工程复杂度比当前硬求交高
- 参数设计和调权重需要实验

### 方案 C：模板匹配 + 参数化重建

流程：

1. 先判断建筑属于哪一类拓扑原型
2. 再根据三视图估计参数
3. 输出体素或 mesh

优点：

- 可控性最高
- 对游戏建筑资产非常友好
- 内部结构更容易合理

缺点：

- 风格自由度较低
- 模板库需要前期积累

如果必须在三者中只选一条快速推进，建议顺序是：

1. `方案 A`
2. `方案 B`
3. `方案 C`

## 四、可参考的其他 AI 生成建模路线

下面这些路线不一定适合直接替换现有方案，但可以作为参考，帮助决定是“继续增强三视图体素法”，还是切换成“AI 先给几何，再体素化”。

## 4.1 多视图一致生成 + 几何重建

代表方向：

- `Wonder3D`
- `Zero123 / Zero123++` 类 novel view 生成
- `CRM`
- `InstantMesh`
- `TRELLIS`

核心思路：

1. 从单图或少量图生成多视角一致图像
2. 同时预测法线、深度或粗几何
3. 再通过 mesh reconstruction 或 implicit surface 得到 3D

对当前问题的启发：

- 它们通常比“只用三张正交图”拥有更多视角约束
- 对被遮挡区域会借助 3D 先验补全
- 更擅长生成整体合理的壳体，而不是纯几何求交

局限：

- 建筑内部仍然是弱项，尤其是完全不可见区域
- 生成结果可控性未必比三视图方案高
- 对像素风和低模规范资产，输出往往还需要二次规整

## 4.2 图像到法线/深度/语义，再做规则重建

这条路线很适合作为你当前方案的增强版，而不是完全替代。

可以让模型额外预测：

- `depth`
- `normal`
- `semantic mask`
- `roof mask`
- `opening mask`

然后用这些中间结果引导体素/mesh 重建。

优点：

- 比直接从 RGB 三视图做占据推断信息更多
- 可以保留现有体素管线
- 比端到端 3D 生成更容易调试

这通常是工程上性价比最高的 AI 增强方式。

## 4.3 先生成 mesh，再做体素化

代表方向：

- `Hunyuan3D` 系列
- `TripoSR`
- `Meshy` 这类产品化模型

思路是：

1. 让 AI 直接生成粗 mesh
2. 再把 mesh 体素化到你的引擎表示里
3. 最后做规则化、像素风化、结构纠正

优点：

- AI 擅长直接补全整体 3D 形状
- 对复杂屋顶、塔楼轮廓往往比正交求交更自然

缺点：

- 建筑的直线、垂直、模块化重复结构容易歪
- 生成 mesh 常常带有艺术噪声，不一定适合体素或游戏关卡资产
- 内部结构仍未必真实

适合做：

- 灵感草模
- 复杂外轮廓候选
- 作为后续规则化重建的参考

不适合直接作为高可控生产方案。

## 4.4 NeRF / 3D Gaussian / implicit field 后再离散化

这条路线学术上常见，但对当前目标不一定最实用。

优点：

- 表面连续性好
- 多视图融合自然

缺点：

- 对游戏建筑资产不够规整
- 转成可控体素结构时损失较大
- 内部遮挡区域同样依赖先验猜测

如果目标是“像素风建筑资产生产”，它更适合作为研究参考，而不是近期主线。

## 五、比较现实的混合路线建议

结合当前需求，比较务实的路线不是完全替换成某个大模型，而是形成下面的混合方案。

### 路线 1：三视图体素法增强版

适合：

- 已有三视图到体素原型
- 更看重可控性和开发成本
- 目标是像素风、低模、规则建筑

建议配置：

1. 三视图输入规范化
2. 屋顶分离
3. 主体壳体重建
4. 开口 carving
5. 模板先验修正
6. 局部高精度 refinement

这是最适合当前阶段的主线方案。

### 路线 2：AI 几何先验辅助体素重建

适合：

- 想保留当前管线
- 但希望 AI 帮忙推断遮挡区域

建议配置：

1. 用图像模型额外输出 depth / normal / semantic
2. 将这些结果作为体素占据先验
3. 最终仍由规则系统做建筑化约束

这是“风险较低、收益较稳”的升级方案。

### 路线 3：AI 先出粗 mesh，规则系统再规整

适合：

- 目标建筑外形复杂
- 更需要快速探索风格形态
- 可以接受后期较强的规整和修模

建议配置：

1. AI 生成粗 mesh
2. 自动提取主平面、屋顶、洞口、对称轴
3. 重建为规则化壳体
4. 再体素化

这条路线更像“概念设计辅助”，而不是稳定生产管线。

## 六、推荐的近期实施顺序

如果目标是近期就能提升“带盖建筑内部细节”效果，建议按以下顺序迭代：

1. **先做屋顶语义分离**
   先解决 `top` 视图把中间全部盖死的问题。

2. **把主体重建从实心占据改成壳体优先**
   默认建筑是“墙体围合空间”，不是“一整块实心体”。

3. **增加开口和回廊 carving**
   让门洞、窗廊、柱廊真正参与挖空逻辑。

4. **加入少量建筑模板先验**
   哪怕只支持 `实心块 / 回字院 / 骑楼 / 中殿` 四类，也会明显提升结果稳定性。

5. **局部高分辨率 refinement**
   把精度用在檐下、内院、洞口，而不是整栋楼平均加密。

6. **再考虑引入 AI 几何先验**
   例如 depth、normal、semantic，而不是一上来全面切换到端到端 3D 生成。

## 七、结论

当前问题的核心并不是“体素算法不够复杂”，而是：

- 三视图对带盖建筑内部细节的信息先天不足
- 现有方法默认把建筑当作实心体求交
- 屋顶在顶视中对占据判断权重过大
- 缺少建筑语义和拓扑先验

因此更合理的优化方向不是继续强化“纯三视图硬求交”，而是转向：

- **壳体优先**
- **屋顶分离**
- **空腔推断**
- **语义分层**
- **建筑模板先验**
- **AI 输出几何中间量辅助重建**

如果只给一个最务实的建议，那就是：

**保留现有三视图 -> 体素主框架，但把“屋顶”从占据判断里拆出来，并把主体重建从“实心体求交”升级为“建筑壳体 + carving + 模板先验”。**

这比完全切换到新的 AI 建模路线成本更低，也更符合建筑资产需要可控、规整、可编辑的目标。
