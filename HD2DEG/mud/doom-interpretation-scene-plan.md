# 算法二开发文档：三视图到 Doom 化场景解释

## 1. 目标与定位

本算法不追求“精确三维重建”，而追求“可走、可读、可扩展”的低精度场景生成。

输入是三视图（front / side / top），输出是偏 Doom / Build 风格的简易建筑场景：

- 有明确地面、墙体、走廊、房间和通道
- 允许做首层入口、广场退让、节点空间
- 便于后续接入第一人称移动和碰撞

一句话：从“像什么”转向“能走、能玩、像关卡”。

---

## 2. 和算法一的关系

- 算法一（求交体素）偏“形体恢复”
- 算法二（场景解释）偏“空间组织”

推荐串联方式：

1. 用算法一得到低精度体块或轮廓参考  
2. 用算法二把它转成可走的 Doom 化场景结构

如果算法一结果不稳定，也可直接使用三视图输入，跳过体素中间层。

---

## 3. 总体流水线

## Stage A：输入标准化

输入：

- `frontMask[x, y]`
- `sideMask[z, y]`
- `topMask[x, z]`

约束：

- 同一原点、同一尺度
- 二值或少量离散颜色
- 推荐低分辨率（例如 32~64）

输出：

- 归一化的三个掩码
- 坐标系映射（x, y, z 对应关系）

## Stage B：平面优先解析（核心）

核心思想：先把 `topMask` 解释为“可行走空间 + 建筑占位 + 道路/庭院”。

建议步骤：

1. 连通域分析，提取主区域（主楼区、侧翼区、空场区）
2. 轮廓简化（矩形化、正交化）
3. 识别窄通道和瓶颈（未来作为门洞、走廊候选）
4. 得到平面语义图层：
   - `walkable`
   - `solid`
   - `void`
   - `portalCandidate`

## Stage C：高度解释

利用 `frontMask` / `sideMask` 估计每个平面区域的高度信息：

- `floorHeight`：默认 0，可按区域做台阶
- `ceilHeight`：由正/侧视图投影统计得出
- `wallHeight = ceilHeight - floorHeight`

启发式建议：

- 高度做离散化（例如 1, 2, 3, 5, 8）
- 小幅抖动并归并，避免噪声高差
- 主体区域更高、通道区域更低

## Stage D：Doom 化结构生成

将区域边界转换为“墙边段 + 门洞段 + 开口段”。

基础元素：

- Sector：区域（地板高、天花板高、材质）
- Wall Segment：边界线段（可封闭或通行）
- Portal：可通行连接（门、拱口、走廊口）

建议输出结构（示例）：

```json
{
  "sectors": [
    {
      "id": "s_main",
      "polygon": [[x1,z1],[x2,z2],"..."],
      "floor": 0,
      "ceiling": 4,
      "material": "stone"
    }
  ],
  "walls": [
    {
      "sectorId": "s_main",
      "a": [x1,z1],
      "b": [x2,z2],
      "type": "solid"
    }
  ],
  "portals": [
    {
      "from": "s_main",
      "to": "s_side_a",
      "segment": [[x1,z1],[x2,z2]],
      "door": true
    }
  ]
}
```

## Stage E：风格化（像素 / 折纸 / 低精度）

风格规则建议：

- 所有坐标落栅格
- 墙厚固定（例如 1 单元）
- 斜边优先台阶化或正交化
- 小碎片删除（最小面积阈值）
- 入口与窗洞采用固定模板尺寸

---

## 4. 数据结构建议

## 4.1 运行时网格（便于算法）

- `cellType[x,z]`：空地/建筑/道路/广场
- `regionId[x,z]`：平面区域归属
- `heightFloor[x,z]`
- `heightCeil[x,z]`

## 4.2 几何层（便于渲染和碰撞）

- `Sector[]`
- `WallSegment[]`
- `Portal[]`
- `Props[]`（门、灯箱、树池、柱）

建议先网格后几何，避免过早进多边形布尔运算。

---

## 5. 关键启发式

## 5.1 非唯一解处理

三视图对应多个三维可能结构，需引入偏好函数：

- 偏好连通
- 偏好简单（边数量少）
- 偏好正交
- 偏好可行走空间连续
- 偏好少而大的区域

可使用加权评分：

`score = a*connectivity + b*simplicity + c*orthogonality + d*walkability - e*fragmentation`

## 5.2 门洞与通道生成

不要把所有窄口都变成门。建议规则：

- 宽度在阈值区间内才是门候选
- 门两侧必须连接不同区域
- 门前后至少有一定深度空间

## 5.3 噪声处理

- 去除面积过小区域（连通域阈值）
- 合并短边、共线边
- 高度孤岛回填到邻域主高度

---

## 6. 和现有 `doom.html` 的接入建议

目标：先低风险接入，不推翻现有渲染。

步骤：

1. 先把算法二输出降级到当前 `MAP + WALL_H` 形式  
2. 利用现有 raycast 管线直接预览  
3. 稳定后再升级到真正 Sector/Portal 结构

过渡期映射：

- `solid wall` -> `MAP = 1`
- `walkable` -> `MAP = 3/4/5`（按语义区分）
- `ceiling/floor` -> 映射到 `WALL_H` 或额外高度表

---

## 7. 里程碑

## M1：平面解释可用

- 能从 `topMask` 生成连通区域
- 能自动给出主通道和房间候选
- 可视化 debug 图可看

## M2：高度解释可用

- front/side 能影响区域高度
- 形成明显层次（主体、侧翼、入口）

## M3：Doom 化导出可跑

- 自动生成墙线和门洞
- 能接入当前第一人称 demo 中游走

## M4：风格化

- 折纸感增强（壳体、简化、台阶化）
- 像素风材质和道具挂接

---

## 8. 验收标准

- 从俯视图看，空间结构清晰（房间、走廊、节点）
- 从第一人称看，能辨认建筑语义（入口、街墙、退让）
- 可走路径连续，不频繁卡死
- 对输入噪声有一定鲁棒性
- 结果整体有 Doom 风格“关卡感”，非单纯体素雕塑

---

## 9. 后续扩展方向

- 自动“主路 + 支路 + 节点广场”布局
- 规则化首层界面（门厅、橱窗、灯箱）
- 基于评分函数的多候选解搜索（Top-K 方案）
- 将算法二输出保存为可编辑关卡 JSON
