# 剧本编辑器 UI 设计文档 v1

## 1. 文档目的

本文档用于定义剧本编辑器后续 UI 改造时的目标效果。

目标不是为当前实现细节服务，而是为后续“真实编辑器完成后按同一 UI 标准还原视觉与布局”提供清晰依据。后续实际改造时，应以本文档为准统一页面职责、布局比例、背景风格、功能排列、字段显隐和适配策略。

参考物料：

- 工作台总布局线框图：`docs/script-editor-workbench-wireframe.svg`
- 人物编辑态线框图：`docs/script-editor-character-editor-wireframe.svg`
- 静态演示页：`docs/script-editor-ui-redesign-demo.html`

若上述参考物料尚未入库，本文档本身仍可作为后续 UI 还原的主依据。

## 2. 设计目标

### 2.1 工作流目标

把“选择/管理剧本项目”和“编辑当前剧本”彻底分开，让工作区只承担创作职责。

### 2.2 使用感目标

编辑器应表现为一个稳定、可长期工作的创作工作台，而不是若干入口按钮堆在一起的工具页。

### 2.3 视觉目标

整体采用“暖色羊皮纸”方向：

- 明亮、正常、可长时间观看
- 保留一定历史题材气质
- 不使用压抑暗底
- 不做花哨、强侵入、强发光效果

## 3. 页面职责边界

### 3.1 剧本列表页负责

- 新建剧本
- 导入现有内容
- 查看已创建剧本
- 继续编辑某个剧本
- 删除某个剧本
- 返回主菜单

### 3.2 编辑工作台负责

- 编辑当前剧本
- 切换当前对象类型
- 切换当前对象实例
- 编辑当前对象属性
- 配置关系与事件
- 保存当前内容
- 校验当前内容
- 导出当前项目
- 返回剧本列表

### 3.3 明确禁止

编辑工作台中不再常驻以下动作：

- 打开项目
- 导入剧本包
- 返回项目入口

这些动作必须留在剧本列表页，不进入工作台常驻首屏。

## 4. 整体布局结构

编辑工作台采用“三栏 + 顶部工具栏”的稳定结构。

### 4.1 顶部工具栏

位于页面顶部，横向排列，仅保留全局动作。

推荐排列顺序：

1. 返回剧本列表
2. 保存
3. 校验
4. 导出

顶部工具栏不承担对象切换，不承担项目导入，也不承担对象级导航。

### 4.2 左侧第一列：主功能导航

这是创作流程的一级入口，采用竖排固定导航。

固定项：

- 人物
- 城市
- 建筑

设计要求：

- 永远可见
- 宽度较窄
- 当前选中项有明确高亮
- 更像“对象类型切换器”，而不是按钮堆

### 4.3 左侧第二列：二级对象列表

用于展示当前一级对象类型下的具体实例。

例如：

- 选中“人物”时显示人物列表
- 选中“城市”时显示城市列表
- 选中“建筑”时显示建筑列表

列表内应包含：

- 搜索入口
- 新增按钮
- 删除按钮
- 列表项

列表项应至少展示：

- 对象名称
- 分类摘要或简要说明
- 必要状态标签

### 4.4 中央主编辑区

中央区是工作台核心，应占据最大可视面积。

职责：

- 展示当前选中对象的详细设置
- 允许直接修改属性
- 允许新增 / 删除扩展属性
- 允许设置关系与事件挂载

中央区不再附带无关入口功能，不再承担项目选择职责。

## 5. 人物编辑态标准布局

人物页作为后续城市页、建筑页的模板页。

### 5.1 上半区：基础信息常驻

人物页上半区固定显示基础信息：

- 人物名称
- 身份 / 分类
- 所属阵营
- 默认所在城市
- 人物简介

这些信息应常驻可见，不应被切页隐藏。

### 5.2 下半区：标签页切换

人物页下半区使用标签页承载复杂配置，推荐标签为：

- 核心属性
- 扩展属性
- 关系绑定
- 事件挂载

设计目的：

- 保留基础信息持续可见
- 降低一次性信息拥挤
- 避免页面无限向下堆叠

### 5.3 核心属性页

核心属性采用固定模板，不做成完全自由字段表。

建议固定项：

- 统率
- 武力
- 智谋
- 魅力
- 野心
- 忠诚

表现方式：

- 使用统一属性卡片或统一表单行
- 强调“角色塑造感”，而不是技术字段感

### 5.4 扩展属性页

扩展属性承载自由扩展内容。

每条扩展属性至少支持：

- 属性名称
- 属性类型
- 属性值
- 属性说明
- 删除属性

页面内需要明确存在：

- `新增属性`
- `删除属性`
- `编辑属性`

### 5.5 关系绑定页

用于配置人物与世界对象之间的关系，例如：

- 关联人物
- 所属城市
- 所属建筑
- 势力归属

### 5.6 事件挂载页

用于配置人物在剧情与系统中的触发入口，例如：

- 初始事件
- 可触发事件
- 特殊剧情入口

## 6. 色彩与背景规范

### 6.1 总体色彩方向

采用“暖色羊皮纸”风格：

- 页面背景：浅米黄、浅羊皮纸色
- 面板底色：柔和浅棕米色
- 边框：低饱和棕金色
- 主强调色：暖金棕
- 危险操作：柔和暗红棕
- 成功状态：低饱和绿色

### 6.2 不允许的方向

- 大面积纯黑 / 深棕暗底
- 强霓虹色
- 紫色主调
- 高饱和冷蓝赛博风
- 过强玻璃拟态和过度发光

### 6.3 文字对比

- 标题：深棕灰，清晰稳定
- 正文：中深棕灰
- 次级说明：柔和灰棕
- 所有文本必须保证在浅底上有足够可读性

## 7. 组件风格规范

### 7.1 面板

- 使用圆角矩形
- 边框清晰但不厚重
- 具备轻微层次，不使用厚重阴影
- 视觉上应像纸面分区，而不是悬浮科技面板

### 7.2 按钮

按钮分三级：

- 主按钮：导出、确认新增等，使用暖金棕强调
- 次按钮：保存、校验，使用浅色面板式按钮
- 危险按钮：删除，使用柔和红棕

### 7.3 列表项

- 当前选中项需要明确高亮
- 未选中项保持安静，不喧宾夺主
- 列表项信息简洁，不塞满技术字段

### 7.4 标签页

- 当前页签高亮
- 其他页签弱化
- 标签页区域不应太厚重
- 页签切换后内容区域保持稳定

## 8. 功能排列规范

### 8.1 全局动作顺序

推荐固定顺序：

1. 返回剧本列表
2. 保存
3. 校验
4. 导出

### 8.2 对象列表动作顺序

推荐固定顺序：

1. 搜索
2. 新增对象
3. 删除对象
4. 对象实例列表

### 8.3 中央区动作顺序

推荐固定顺序：

1. 基础信息
2. 核心属性
3. 扩展属性
4. 关系绑定
5. 事件挂载

不得把对象级操作散落在顶部、左侧、底部多个位置，避免焦点混乱。

## 9. 响应式适配原则

### 9.1 宽屏

- 保持三栏结构稳定
- 左侧双列清晰，中间编辑区最大化

### 9.2 中等宽度

- 顶部按钮允许换行，但顺序不变
- 二级对象列表允许稍微收窄
- 中央编辑区保持优先面积

### 9.3 窄屏

- 左侧二级列表可切为抽屉或覆盖层
- 一级导航尽量保留
- 中央编辑区优先保住
- 不允许因为适配导致创作者频繁跳出当前对象编辑上下文

## 10. 字段显隐联动要求

后续 UI 改造必须同时遵循 `docs/script-editor-field-visibility-spec.md`：

- 主区不显示人物 ID
- 主区不显示内部 key
- 主区不显示 runtime / compatibility 技术字段
- 技术字段仅进入高级层或调试层

## 11. 验收标准

当以下条件全部满足时，可认定 UI 改造符合本文档：

- 工作台中不再常驻项目选择动作
- 左侧主导航固定为对象类型竖排导航
- 左侧二级列表承担对象实例切换
- 中央区承担对象主要编辑工作
- 人物页采用“基础信息常驻 + 下半区标签页”的结构
- 视觉整体为明亮、稳定、暖色羊皮纸风格
- 技术字段未侵入主创作流
- 在桌面与中宽度下都能维持清晰的创作工作流

## 12. 后续落地方向

当真实剧本编辑器功能完成后，UI 改造应优先按以下顺序推进：

1. 先完成页面职责拆分
2. 再完成工作台结构改造
3. 再按本文档统一组件排列
4. 最后统一替换色彩、背景、按钮、列表、标签页视觉

这样可以避免先换皮，再返工结构。
