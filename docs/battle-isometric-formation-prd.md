# 等轴编队战棋改造 PRD

本文定义当前战棋原型后续改造成“等轴 2.5D 地图层 + 九宫格编队演出层”的产品与机制规格。它不是当前实现说明；当前实现仍以 [battle-demo-current-design.md](/D:/RPG_TG/docs/battle-demo-current-design.md) 为准。

## 1. 目标

- 将战斗地图从正交平面网格升级为等轴 2.5D 视角。
- 地图块统一表现为带黄色边缘、圆角的等轴正方形。
- 棋盘上的可操作对象从“单一兵种单位”改为“混编编队”。
- 步兵、长枪、骑兵、弓兵、火器等不再是棋盘单位本身，而是每个棋盘编队内部 3x3 阵位里的成员。
- 玩家操作流程改为“点击编队 -> 显示移动范围 -> 点击目标格临时移动 -> 显示行为与攻击范围 -> 选择行为后锁定”。
- 攻击不再直接在棋盘格上完成数值结算，而是进入类似《战争交响曲》的战斗演出界面。
- 战斗演出中双方编队分列左右，以 3x3 九宫格展示，攻击方先攻，防守方还击，重复两轮。

## 2. 设计原则

- 地图层只处理位置、移动、可攻击目标、据点、地形和行动承诺。
- 编队层处理具体兵种、阵位、射程、克制、士气、伤害和演出。
- 一次棋盘攻击必须能回写为结构化结果：成员兵力、编队士气、状态、溃逃、主将受损等。
- 改造应复用 [battle-formation.ts](/D:/RPG_TG/src/domain/battle-formation.ts) 的 3x3 编队概念，而不是在原型页面里重新定义一套阵位。
- 后续正式接入应新增 `src/application/battle`，由 application 层输出结构化战斗 view model，UI 层只负责渲染和交互事件回传。

## 3. 地图视觉

### 3.1 等轴地图

- 底层坐标第一版仍保留矩形网格坐标，视觉层做等轴投影。
- 每个逻辑格渲染为一个等轴菱形视角的圆角正方形地块。
- 地块之间保留间隙，避免点击热区重叠。
- 点击判定仍绑定逻辑格，视觉地块需要有稳定的 `x/y` 坐标映射。

### 3.2 地块外观

所有地块都使用黄色边缘，不只限于可交互格。

- 普通地块：地形底色 + 黄色细边。
- 当前选中编队所在格：黄色高亮边 + 轻微抬升。
- 可移动范围：青蓝色半透明覆盖。
- 临时移动目标格：亮黄色边 + 行为菜单锚点。
- 攻击范围：红色半透明覆盖。
- 攻击范围内有敌人的格：红色强调边 + 敌方编队轮廓高亮。
- 已行动编队：降低饱和度或透明度，但仍保留可读性。

## 4. 玩家交互流程

### 4.1 状态 A：未选择编队

玩家点击己方未行动编队后：

- 选中该编队。
- 显示该编队从当前位置出发的移动范围。
- 不立即显示攻击范围。
- 显示编队摘要：主将、总兵力、士气、阵型、主要兵种。

### 4.2 状态 B：选择移动目标

玩家点击移动范围内的地块后：

- 编队临时移动到该地块。
- 系统记录移动前位置。
- 显示从新位置计算出的攻击范围。
- 显示该地点可执行行为菜单。
- 若攻击范围内存在敌方编队，菜单包含“攻击”。
- 若没有可攻击目标，菜单只包含非攻击行为。

### 4.3 状态 C：移动后未确认行为

在正式选择行为前：

- 右键回退到移动前位置。
- 回退不消耗行动。
- 回退后恢复显示原始移动范围。
- 玩家可以重新选择移动目标。

### 4.4 状态 D：行为已确认

选择任一正式行为后不可撤回。

- 待机：结束该编队行动。
- 整顿：执行整顿效果并结束行动。
- 攻击：选择目标并进入战斗演出，演出结算后结束行动。

行为确认后，右键不再能撤销本次移动。

## 5. 行为菜单

### 5.1 待机

待机用于确认当前位置并结束行动。

- 若位于可占领据点上，推进占领流程。
- 若位于己方营寨或补给范围内，可获得据点提供的恢复。
- 无额外条件时，仅结束行动。

### 5.2 整顿

整顿是移动后的非攻击行动。第一版采用组合效果：

- 恢复编队士气。
- 尝试降低或清除负面状态，例如混乱、动摇、阵型紊乱。
- 小幅恢复编队组织度；若后续存在轻伤/散兵概念，可恢复少量可恢复兵力。
- 原地整顿强于移动后整顿。

建议初版数值：

- 移动后整顿：士气 +8，降低 1 层轻度负面状态。
- 原地整顿：士气 +12，降低 1 层负面状态，并恢复少量组织度。
- 溃逃编队不可主动整顿；后续可另做“收拢溃兵”机制。

### 5.3 攻击

攻击行为分两步：

1. 玩家点击“攻击”。
2. 地图高亮可攻击敌方编队，玩家点击目标后进入演出。

攻击确认后：

- 不可撤回移动。
- 不在地图层直接套用旧 `calcDamage`。
- 进入编队战斗演出并以演出结算为准。

## 6. 攻击范围与射程

### 6.1 地图层攻击范围

编队的地图攻击范围用于决定“哪些敌方编队可被选为目标”。

第一版采用降级兼容式处理，参考《战争交响曲》：

- 如果双方编队距离为 1，则视为接战，编队内所有成员都可以参与攻击。
- 如果双方编队距离为 2，则只有射程大于等于 2 的成员可以参与攻击，射程小于 2 的成员不能攻击。
- 如果双方编队距离为 3 或以上，则只有射程达到该距离的成员可以参与攻击。
- 编队是否能发起地图攻击，由编队内至少一名可行动成员的射程覆盖目标决定。

### 6.2 地图攻击范围显示

- 以编队内最高有效射程计算可选敌方编队。
- 攻击范围覆盖格可以显示，但真正进入演出后，每个成员是否出手要按自身射程重新判定。
- 如果目标在范围内但只有部分成员能攻击，目标预览需要提示“远程交战”或“部分成员可出手”。

### 6.3 地形影响

地形影响分两层：

- 地图层：影响移动、视野、目标锁定。
- 演出层：影响参与成员、命中、伤害、士气或先手。

第一版保留现有地形语义：

- 森林降低远程锁定能力，并限制骑兵冲锋。
- 高地提高视野和远程压制。
- 河流增加受击风险。
- 桥梁作为战术 choke point。

## 7. 编队结构

### 7.1 棋盘单位

棋盘单位是编队，不是单兵种。

建议地图运行时结构：

```ts
type BattleMapFormationUnit = {
  id: string;
  side: "player" | "enemy";
  formationId: string;
  commanderId: string;
  x: number;
  y: number;
  movement: number;
  morale: number;
  acted: boolean;
  movedFrom?: { x: number; y: number };
};
```

### 7.2 编队九宫格

标准编队使用 3x3 阵位：

| 前左 | 前中 | 前右 |
| --- | --- | --- |
| 中左 | 中中 | 中右 |
| 后左 | 后中 | 后右 |

行定位：

- 前排：承伤、近战、长枪、重甲。
- 中排：主将、副将、火器、支援。
- 后排：弓弩、谋士、辎重、鼓舞。

### 7.3 初始编队方案

当前 5 支玩家单位应转换为混编编队，而不是继续保持单兵种棋子。

第一版建议提供 3-5 个预设混编编队：

- 先锋编队：步兵 + 长枪 + 少量弓兵。
- 突击编队：骑兵 + 步兵 + 支援。
- 射击编队：弓兵 + 火器 + 前排护卫。
- 守备编队：步兵 + 长枪 + 主将居中。
- 机动编队：骑兵 + 斥候 + 少量远程。

后续再扩展编队编辑 UI。

## 8. 战斗演出

### 8.1 进入条件

当玩家选择攻击目标后：

- 地图层锁定攻击方、目标方和发起位置。
- 根据双方编队、距离、地形生成战斗演出输入。
- 切换到战斗演出界面。

### 8.2 布局

- 左侧显示攻击方 3x3 编队。
- 右侧显示防守方 3x3 编队。
- 每个阵位显示成员兵种、兵力、状态和是否本轮可攻击。
- 主将阵位高亮。
- 当前出手成员和受击目标要有明显动效或高亮。

### 8.3 回合流程

“两回合”定义为攻防交换重复两次：

1. 第一轮：攻击方所有满足条件的成员依次出手。
2. 第一轮：防守方所有满足条件的成员依次还击。
3. 第二轮：攻击方所有满足条件的成员依次出手。
4. 第二轮：防守方所有满足条件的成员依次还击。
5. 汇总结算，返回地图。

### 8.4 出手规则

每轮不是只挑部分成员，而是所有满足条件的成员都尝试出手。

成员能否出手由以下因素决定：

- 该成员仍有兵力。
- 该成员未被眩晕、溃散或其他强控制状态阻止。
- 该成员射程覆盖当前交战距离。
- 该成员所在阵位没有被规则限制，例如后排近战无法主动打到远距离敌人。

距离为 1 时，所有有战斗能力的成员都可以攻击。

距离大于 1 时，成员射程不足则不能攻击。

### 8.5 目标选择

第一版目标选择可以使用稳定优先级：

- 前排未破时，近战优先攻击敌方前排。
- 远程可优先攻击前排，也可根据兵种规则攻击中后排。
- 骑兵若触发突破，可尝试攻击后排或制造士气打击。
- 长枪对骑兵保持克制。
- 主将被直接攻击或中排暴露时，造成额外士气压力。

### 8.6 结算回写

演出结束后必须回写：

- 双方成员兵力。
- 双方编队总兵力。
- 双方编队士气。
- 主将是否受损或阵亡。
- 编队是否混乱、动摇或溃逃。
- 是否触发胜负条件。

## 9. UI 反馈

### 9.1 地图层反馈

必须清楚表达：

- 当前选中编队。
- 移动范围。
- 临时移动后的位置。
- 可右键撤销状态。
- 当前可执行行为。
- 攻击范围。
- 可攻击敌方编队。
- 行为确认后不可撤回。
- 已行动状态。

### 9.2 演出层反馈

必须清楚表达：

- 当前第几轮。
- 当前阶段：攻击方出手 / 防守方还击。
- 当前出手成员。
- 被攻击目标。
- 伤害数字。
- 士气变化。
- 克制、冲锋、高地、混乱等关键修正。
- 跳过和加速按钮。

## 10. AI 调整

敌方 AI 应遵循同样的“移动后选择行为”模型。

推荐决策顺序：

1. 枚举可移动格。
2. 对每个格计算可攻击目标。
3. 评估每个目标的演出预期收益。
4. 若攻击收益足够，移动后攻击。
5. 若无合适攻击，移动到战略目标位置。
6. 如果低士气或负面状态严重，优先整顿。
7. 否则待机或占点。

评分因素：

- 是否能攻击低士气敌军。
- 是否能攻击主将编队。
- 是否能让更多成员参与攻击。
- 是否能让骑兵近距离接战。
- 是否能让远程保持距离。
- 是否占据高地、森林、桥梁、据点。
- 是否需要保护己方主将。

## 12. 验收标准

- 地图视觉为等轴 2.5D。
- 所有地块都有黄色边缘和圆角。
- 点击己方未行动编队后显示移动范围。
- 点击移动范围内地块后临时移动，并显示行为菜单与攻击范围。
- 未选行为前右键可撤销移动。
- 选择待机、整顿或攻击后不能撤销。
- 攻击目标选择后进入战斗演出界面。
- 演出界面双方按 3x3 编队排列。
- 攻方全员按规则出手，守方全员按规则还击，流程重复两轮。
- 距离为 1 时所有可战斗成员都能攻击。
- 距离大于 1 时射程不足成员不能攻击。
- 当前棋盘单位已从单兵种棋子改为混编编队。
- 战斗演出结果能回写地图层，并影响后续胜负判断。

## 13. 已确认决策

- 黄色边缘应用于全部地块。
- 整顿采用士气恢复、负面状态处理和组织度/可恢复兵力恢复的组合效果。
- 两回合是“攻击方出手 -> 防守方还击”重复两次。
- 每轮所有满足条件的成员都出手。
- 初始棋盘单位改为混编编队。
- 攻击距离采用《战争交响曲》式降级兼容：距离 1 全员可攻，距离 2 起按成员射程过滤。
