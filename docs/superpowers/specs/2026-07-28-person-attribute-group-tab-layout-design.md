# 人物模块属性组 Tab 布局设计

## 背景

当前人物模块已经引入 `attributeMappings`、`attributeValues` 和 `attributeGroup` 作为人物实例属性与属性分组的作者面数据来源，但“属性组”Tab 的展示方式和交互方式仍未收敛。

本次目标是只调整作者面的人物属性组展示与交互，不改运行时读取协议，不引入兼容层。

## 目标

在人物模块中提供一个可用的“属性组”Tab，用于把当前人物实例已有属性编组展示。

要求如下：

- 属性组页只负责“编组”，不负责编辑属性值。
- 组内属性用卡片形式展示。
- 单个属性卡片只显示“属性名”。
- 卡片右上角提供“从该组移出”的删除按钮。
- 每个属性组内每行最多显示 `5` 个属性卡片。
- 每个属性组内最多显示 `2` 行，即单页最多 `10` 个属性卡片。
- 属性组内属性超过 `10` 个时，使用组内独立分页。
- 属性组列表页每页最多显示 `3` 个属性组。
- 属性组列表超过 `3` 个时，使用属性组列表独立分页。
- 点击“添加属性”后，从当前人物实例已有属性中选择并加入组。

## 非目标

- 不修改运行时人物属性读取协议。
- 不在属性组页展示属性类型和值。
- 不在属性组页直接编辑属性值。
- 不引入人物属性组的拖拽排序。
- 不调整城市、建筑等其他作者面属性编辑布局。

## 数据模型

本次不改人物属性分组存储结构，继续使用：

```ts
attributeGroup: Record<
  string,
  {
    title: string;
    order: number;
    attributeKeys: string[];
  }
>;
```

人物实例属性来源继续使用：

```ts
attributeMappings: Array<{
  key: string;
  keyName: string;
  type: "number" | "string" | "boolean" | "enum";
}>;

attributeValues: Array<{
  key: string;
  value: string | number | boolean;
}>;
```

作者面“属性组”Tab 的展示数据由 `attributeMappings + attributeValues` 派生：

- 卡片显示名：`attributeMappings[i].keyName`
- 卡片关联 key：`attributeMappings[i].key`
- 属性组成员关系：`attributeGroup[groupId].attributeKeys`

## 交互设计

### 1. 属性组列表

属性组 Tab 内展示属性组卡片列表。

每页最多显示 `3` 个属性组卡片：

- 超出后显示上一页 / 下一页分页控件
- 切页时列表高度保持稳定

每个属性组卡片包含：

- 组名输入框
- `添加属性` 按钮
- 组内属性卡片网格
- 删除该组按钮

### 2. 组内属性卡片

组内属性使用卡片网格展示：

- 每行 `5` 个
- 最多 `2` 行
- 单页最多 `10` 个
- 超出后显示组内分页控件

单个属性卡片只显示：

- 属性名（`keyName`）
- 右上角删除按钮

删除按钮语义：

- 仅从当前属性组移出该属性
- 不删除该人物实例的属性本体

### 3. 添加属性

点击某个属性组的 `添加属性` 按钮后，打开当前组的属性选择面板。

选择面板数据源：

- 当前人物实例已有属性
- 包含自定义属性
- 显示名使用 `keyName`

过滤规则：

- 已经在当前组里的属性不再出现在候选列表中

选择行为：

- 点击某个候选属性，立即加入当前组
- 加入后关闭当前组的选择面板

## 状态设计

作者面需要维护以下 UI 状态：

- `scriptEditorPersonAttributeGroupPage`
  - 属性组列表当前页
- `scriptEditorPersonAttributeGroupOpenPickerId`
  - 当前展开“添加属性”面板的组 id
- `scriptEditorPersonAttributeGroupItemPageById`
  - 每个属性组自己的属性卡片分页状态

约束：

- 这些状态仅用于作者面展示
- 不写入导出的剧本包人物数据

## 布局与样式

### 自定义属性区

保留现有“自定义属性”区的作者面职责，但继续隐藏运行时 `key`：

- 创作者不可见 `key`
- 创作者可编辑 `keyName / type / value`

### 属性组区

新增或扩展以下样式语义：

- 属性组列表固定高度
- 属性组卡片固定内边距与边框风格，保持与现有作者面统一
- 组内属性卡片区固定两行高度
- 组内分页区域固定在卡片底部
- 候选属性选择面板使用轻量下拉 / 面板样式，不引入模态层

## 实现边界

本次实现只涉及人物作者面相关代码：

- `src/ui/main-ui/main-ui-flow.js`
- `src/styles/script-editor.css`
- 必要时补充 `tests/robustness.test.cjs`

如需增加人物作者面辅助状态或分页辅助方法，应保持在人物作者面域内，不扩散到运行时。

## 错误处理

- 若某组没有属性，显示空状态区域，但保留 `添加属性` 按钮。
- 若当前人物没有任何可选属性，点击 `添加属性` 后显示“无可添加属性”提示。
- 若删除属性后当前页为空，应自动回退到前一有效页。
- 若删除属性组后当前属性组列表页为空，应自动回退到前一有效页。

## 测试策略

至少覆盖以下检查：

- 人物模块 Tab 列表包含 `attribute-group`
- `selectScriptEditorPersonTab()` 接受 `attribute-group`
- 自定义属性编辑区不再暴露运行时 `key`
- 属性组面板存在 `添加属性`、组名输入、组内卡片和删除动作
- 属性组数据源来自人物实例属性，而不是旧的 `extendedAttributes` 硬编码路径
- 属性组列表分页和组内属性分页的渲染入口存在

## 风险

### 1. 旧人物作者面方法残留覆盖新方法

当前文件中已经出现过同名人物作者面方法重复定义，后定义覆盖前定义会导致 Tab、属性展示或事件入口错乱。

本次实现必须先保证人物作者面只保留一套生效逻辑。

### 2. 旧 `label / extendedAttributes` 路径污染

如果属性组页仍然读旧的 `extendedAttributes` 或 `label`，会导致：

- `keyName` 显示不正确
- 自定义属性运行时 key 再次暴露
- 属性组候选数据源不一致

因此属性组页必须统一读取人物实例属性派生结果。

## 结论

采用方案 `A`：

- 属性组页极简展示
- 组头 `添加属性`
- 组内卡片只显示属性名
- 属性组列表与组内属性均做固定高度分页

这是当前人物作者面下最小、最稳定、最符合现有密度的实现方案。
