# 编队机制设计基线

本文定义后续合战系统的编队、占用规模和属性换算基线。目标是把《战争交响曲》式的“一个战场棋子内部有编成取舍”落到本项目的太阁式历史模拟框架中，同时兼容当前战棋原型的固定部队池。

## 设计目标

- 战场上仍以“编队”为最小可操作棋子，避免把当前战棋 Demo 扩成大量单兵单位。
- 编队内部由主将、士兵小队和可选副将/支援位构成。
- 主将统率不直接堆伤害，而是外化为更高编队容量、更稳士气和更强协同。
- 阶段性内容通过数据控制，容量公式、阵位和校验留在共享领域模块。

## 阶段规模

| 阶段 | 可拥有编队 | 可出战编队 | 单编队容量 |
| --- | ---: | ---: | ---: |
| 流民 / 小股义军 | 2-3 | 2-3 | 6-8 |
| 小寨 / 军府成长期 | 4-6 | 3-4 | 8-12 |
| 一方势力 | 6-10 | 5-6 | 12-16 |
| 大战役 | 10+ | 6-8 | 16-20 |

当前战棋原型已有 5 支固定部队池，因此第一版建议使用“玩家最多 5 个编队、单场部署 3-5 个编队”的节奏。

## 阵位

标准编队使用 3x3 阵位：

| 前排 | 前排 | 前排 |
| --- | --- | --- |
| 中排 | 中排 | 中排 |
| 后排 | 后排 | 后排 |

行定位：

- 前排：承伤、近战、长枪、重甲。
- 中排：主将、副将、火器、支援。
- 后排：弓弩、谋士、辎重、鼓舞。

基础规则：

- 近战单位在前排完整发挥，中排降低发挥，后排不主动近战。
- 远程单位后排更安全，但当前排被突破时更容易受伤。
- 长枪前排克骑兵，骑兵突破后排时制造士气压力。
- 主将被击破或中排暴露时，编队士气大幅下降。

## 占用规模

占用规模表示指挥负担，不等同于真实人数。

| 单位类型 | 占用规模 | 说明 |
| --- | ---: | --- |
| 民兵、乡勇、斥候 | 1 | 低成本补位 |
| 普通步卒、弓手、长枪兵 | 2 | 基础主力 |
| 精锐步卒、弩手、火器、轻骑 | 3 | 有明确战术价值 |
| 重骑、亲兵、重甲步队 | 4 | 高强度核心 |
| 攻城器械、特殊支援队 | 5 | 强功能单位，限制数量 |

主将不占容量。副将是否占容量由后续身份设计决定；如果副将自带独立战斗小队，则应按对应兵种占容量。

## 容量公式

共享领域模块使用以下公式：

```text
编队容量 = 基础容量 + 统率加成 + 军学加成 + 官职加成 + 特性加成
基础容量 = 6
统率加成 = floor(统率 / 20)
军学加成 = floor(军学等级 / 2)
最大容量 = 20
```

示例：

```text
统率 70，军学 3，官职 +1
容量 = 6 + 3 + 1 + 1 = 11
```

## 兵种发挥率

兵种发挥率用于把主将能力与具体兵科适性分开：

```text
发挥率 = 80% + 对应技能等级 * 4% + floor(统率 / 5)%
上限 = 130%
```

示例：

```text
统率 70，骑马 3
骑兵发挥率 = 80 + 12 + 14 = 106%
```

这样强将能稳定带兵，但仍需要足轻、骑马、铁炮、弓术、水军等兵科技能支撑对应兵种。

## 当前代码落点

- 领域类型与纯计算函数位于 `src/domain/battle-formation.ts`。
- 该模块目前只定义编队容量、阵位、占用规模、校验和兵种发挥率。
- 暂不接入 `src/main.ts`，也不改变现有战棋 Demo 行为。
- 后续接入战斗时，应新增 `src/application/battle` 服务读取编队结构，再向 UI 输出结构化战斗视图模型。

## 后续接入顺序

1. 定义基础兵种数据表。

3. 增加编队编辑 UI。
4. 让战棋 Demo 的“5 支部队”改为“3-5 个编队棋子”。
