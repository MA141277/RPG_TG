# Agent Immediate Execution Workflow

这份文档定义仓库内 agent 的执行期工作流约束。它不是沟通风格建议，而是任务执行规则。

## 1. 适用范围

除非用户明确要求本轮只做以下之一，否则本规则默认适用于当前仓库中的 agent 工作：

- 只讨论方案
- 只写计划
- 只做评审
- 只解释代码
- 只回答问题且用户明确不要改文件或执行命令

如果任务允许在当前工作区直接推进实现、修复、补文档、补验证或同步治理，agent 必须遵守本规则。

## 2. 下一刀定义

“下一刀”指当前上下文下已经足够明确、可以立即执行、并且能够实质推进任务完成的最小下一步。

这里的“下一刀”也包括 agent 在本轮对话中已经主动提出、建议、承诺、或明确识别出来的那个可执行切片。

典型例子包括：

- 可以直接修改的代码或文档
- 可以直接运行的验证命令
- 可以直接补齐的测试、治理记录或镜像同步
- 可以直接完成的局部重构或契约收口

它不是最终完整方案，也不是对后续所有步骤的穷举；它只要求当前最小可执行切片已经清楚。

## 3. 立即执行规则

一旦识别出下一刀，agent 不得把“我接下来要做什么”当作 final answer 汇报然后停住。

agent 必须立即执行这一刀，允许在执行前通过 commentary 说明将要做的动作，但说明不能替代执行本身。

允许的行为：

- 先发简短 commentary 说明即将修改或验证什么
- 立刻动手改文件、运行命令、补测试、补文档或继续下一个已明确切片

不允许的行为：

- 已经知道下一刀，却只在 final answer 里描述它
- 用“建议下一步”“后续可以”“你可以让我继续”替代当前可执行动作
- 因为任务还没整体完成，就把当前明确切片搁置不做

## 4. 阻塞条件

只有遇到明确阻塞条件时，agent 才可以不立即执行下一刀。

明确阻塞条件包括：

- 缺少完成该刀所必需的用户输入、文件、资源或外部结果
- 继续执行会违反用户的显式边界
- 继续执行会触发高风险或破坏性动作，而当前没有用户明确授权
- 工作区出现直接冲突，无法在不猜测用户意图的前提下安全推进
- 当前仓库规则要求先满足另一个前置合同，而该前置条件尚未满足

如果出现阻塞，agent 必须明确指出阻塞点，以及为什么这使当前下一刀不可执行。

## 5. Final Answer Gate

只有在以下任一条件成立时，agent 才可以输出 final answer：

- 当前请求范围内已经没有剩余的可执行下一刀
- 剩余工作全部依赖明确阻塞条件解除
- 用户明确要求此轮停止在分析、方案、计划或评审层

如果还有明确且可执行的下一刀，final answer 不是允许选项。

## 6. Final Answer Precheck Rule

在任何 final answer 之前，agent 必须先判断当前是否仍存在明确且安全的可执行下一刀。

如果存在这样的下一刀，尤其是 agent 已经在当前回复中提出、建议、承诺、或明确点名要执行的下一刀：

- 禁止输出 final answer
- 必须继续执行该切片

如果 agent 不执行，则必须明确记录阻塞条件，并说明为什么该阻塞使这一步当前不可执行。

这个 precheck 不是可选建议；它是 final answer 的前置门。

## 7. 汇报方式

在执行过程中，agent 应使用 commentary 持续汇报进展，而不是用 final answer 提前收束工作。

final answer 应只用于：

- 交付已经实际完成的结果
- 说明已经执行过的验证
- 说明仍然存在且确实阻塞后续推进的问题

final answer 不能把“尚未执行但已经明确可做的下一刀”包装成完成汇报。

## 8. 与仓库治理的关系

本规则不替代其他治理文档；它约束的是“何时必须继续执行”，不是“具体应该怎么实现”。

如果其他仓库规则要求先读合同、先镜像 scenario pack、先更新 change log、先补验证或先通过某个共享机制推进，agent 仍必须遵守那些规则；但在这些前提已经满足后，只要下一刀可执行，就必须继续落刀。
